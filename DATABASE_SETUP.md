# Database setup (MongoDB)

This guide covers everything needed to connect the portfolio to MongoDB:
where to get a database, which values to configure, how to create the admin
account, how to deploy, and what to do when something goes wrong.

> **Never paste real passwords or connection strings into issues, chats or
> commits.** Every value below is a placeholder. Real values belong only in
> your local `.env` file and in your hosting provider's environment settings.

## 1. Choose where MongoDB runs

| | MongoDB Atlas (recommended) | Local MongoDB |
| --- | --- | --- |
| Use for | Production **and** development | Development only |
| Cost | Free tier (M0, 512 MB) is plenty for a portfolio | Free |
| Works with Vercel/Render | Yes | No (your computer isn't reachable) |

**Recommendation:** use **MongoDB Atlas** — the deployed site needs a database
on the internet, and using the same kind of database locally avoids surprises.
Use a *separate* database user (and ideally a separate database name) for local
development and production.

### Option A — MongoDB Atlas (step by step)

1. **Create an account** at <https://www.mongodb.com/cloud/atlas/register>.
2. **Create a cluster.** Choose the free **M0** tier. Pick a cloud region close
   to where the site is hosted (Vercel's default functions region is
   Washington, D.C. → AWS `us-east-1`).
3. **Create a database user** — *Security → Database Access → Add New Database User*:
   - Authentication: **Password**. Username, e.g. `portfolio-app`.
   - Click **Autogenerate Secure Password** and store it in your password manager.
   - Privileges: choose **Specific Privileges → `readWrite`** on database
     `su_portfolio` (least privilege). *Read and write to any database* also
     works but grants more than needed. Never use `atlasAdmin` for the app.
4. **Allow network access** — *Security → Network Access → Add IP Address*:
   - For local development: **Add Current IP Address**.
   - For Vercel or other serverless hosts (no fixed IP): **Allow Access from
     Anywhere** (`0.0.0.0/0`). See [Security guidelines](#7-security-guidelines)
     for why this is acceptable here and the safer alternatives.
5. **Copy the connection string** — *Database → Connect → Drivers → Node.js*.
   It looks like this:

   ```text
   mongodb+srv://<db-username>:<db-password>@<cluster-name>.<id>.mongodb.net/?retryWrites=true&w=majority&appName=<cluster-name>
   ```

   Replace `<db-password>` with the user's password. If the password contains
   special characters, URL-encode them: `@` → `%40`, `:` → `%3A`, `/` → `%2F`,
   `?` → `%3F`, `#` → `%23`, `%` → `%25`. (An autogenerated password usually
   contains only letters and digits.)
6. Put the string in `.env` as `MONGODB_URI` (next sections) and run
   `npm run db:check`.

### Option B — Local MongoDB (development only)

- **Installer:** MongoDB Community Server from
  <https://www.mongodb.com/try/download/community> (it runs as a service on
  port 27017).
- **Docker:** `docker run -d --name su-mongo -p 27017:27017 mongo:7`

Then use:

```env
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DB_NAME=su_portfolio_dev
```

## 2. Values you need to provide

| Value | Where it comes from | Where it goes |
| --- | --- | --- |
| **MongoDB connection string** (`MONGODB_URI`) | Atlas → Connect → Drivers (or `mongodb://127.0.0.1:27017` locally) | `.env` locally; hosting provider's environment variables in production |
| **Database name** (`MONGODB_DB_NAME`, optional) | You choose, e.g. `su_portfolio` | Same places as above |
| **Admin email and password** | You choose. The password needs **12+ characters** (a passphrase of a few words works well) | Typed into `npm run admin:create` — never stored in any file |

That is all. In particular:

- **No JWT or session secret is required.** Admin sessions are random 256-bit
  tokens stored in an httpOnly cookie; the database keeps only a SHA-256 hash
  of each token, so a leaked database cannot be used to sign in.
- **No image storage service is required.** Uploaded images are stored in the
  same MongoDB database (GridFS).
- **No admin password is stored anywhere except as a scrypt hash** in the
  `admins` collection.

## 3. Environment configuration

Copy the template and fill it in:

```bash
cp .env.example .env        # PowerShell: Copy-Item .env.example .env
```

Complete `.env.example` (placeholders only — the same file is in the repository):

```env
# ── MongoDB (required) ──────────────────────────────────────────────────────
# Atlas: Database → Connect → Drivers. Local: mongodb://127.0.0.1:27017
# URL-encode special characters in the password (@ → %40, : → %3A, / → %2F).
MONGODB_URI=mongodb+srv://<db-username>:<db-password>@<cluster-host>/?retryWrites=true&w=majority&appName=<app-name>

# Database name. Optional — defaults to "su_portfolio" (or the name in the URI path).
MONGODB_DB_NAME=su_portfolio

# ── Admin sessions (optional) ───────────────────────────────────────────────
# Hours an idle admin session stays signed in (renewed while you are active).
SESSION_TTL_HOURS=12

# ── Server (optional) ───────────────────────────────────────────────────────
# Port for the local API and for `npm start`. Most hosts set PORT themselves.
PORT=5050

# Extra site origins allowed to send admin requests, comma-separated.
# Only needed if the API sits behind a proxy on a different host.
ALLOWED_ORIGINS=

# Reverse proxies in front of the server (1 for Vercel/Render/Railway/nginx).
TRUST_PROXY=1

# ── One-time admin creation (optional) ──────────────────────────────────────
# Only for `npm run admin:create` in a non-interactive shell. Delete afterwards.
# ADMIN_EMAIL=you@example.com
# ADMIN_PASSWORD=<a-long-unique-password>
# ADMIN_NAME=Your Name
```

### All environment variables

| Variable | Required | Default | Purpose |
| --- | --- | --- | --- |
| `MONGODB_URI` | **Yes** | — | MongoDB connection string. |
| `MONGODB_DB_NAME` | No | `su_portfolio`, or the database named in the URI path | Which database to use. |
| `SESSION_TTL_HOURS` | No | `12` | How long an idle admin session lasts. Activity renews it; every session ends after 7 days regardless. |
| `PORT` | No | `5050` | Port of the local API and of `npm start`. Hosts like Render set it automatically. |
| `ALLOWED_ORIGINS` | No | — | Extra origins (e.g. `https://www.example.com`) allowed to send admin requests when a proxy changes the host name. Same-origin requests are always allowed. |
| `TRUST_PROXY` | No | `1` | Number of reverse proxies in front of the server (used for client IPs in rate limiting and HTTPS detection). |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` | No | — | Only for non-interactive `npm run admin:create`. Remove them afterwards. |
| `TEST_MONGODB_URI`, `TEST_MONGODB_DB_NAME` | No | — | Only for the API integration tests. **That database is wiped.** |

> ⚠️ Never prefix these variables with `VITE_`. Vite copies `VITE_*`
> variables into the public JavaScript bundle. The server-side variables above
> are never sent to the browser.

## 4. Connecting and verifying the connection

**Where the connection is configured:** `server/config.js` reads the
environment variables (and loads `.env` locally via `server/env.js`), and
`server/db.js` opens the connection with Mongoose. One connection is reused for
all requests (and across warm serverless invocations); nothing needs to be
edited in code.

**Verify it** in any of these ways:

1. **CLI check** (recommended):

   ```bash
   npm run db:check
   ```

   Expected output on success:

   ```text
   Connecting to mongodb+srv://<credentials>@cluster0.xxxxx.mongodb.net/ …

   ✔ Connected to database "su_portfolio" (MongoDB 8.0.x).
     Collections: admins, images.chunks, images.files, loginattempts, profiles, projects, sessions
     Projects:    3 total, 3 published
     Profile:     saved
     Admins:      1
   ```

   On failure it prints a specific hint (wrong password, IP not allowed, host
   not found…). The credentials in the URI are never printed.

2. **Dev server log:** `npm run dev` prints `[api] Connected to MongoDB.` or
   the reason it could not connect.

3. **Health endpoint:** open `/api/health` (locally
   <http://localhost:5173/api/health>):

   ```json
   { "status": "ok", "database": "connected" }
   ```

   `"database": "not_configured"` means `MONGODB_URI` is missing;
   `"unreachable"` means it is set but the connection fails.

## 5. Database initialization and the admin account

Run these once per database (local and production each get their own):

```bash
npm run db:init        # collections + indexes (safe to re-run)
npm run db:seed        # import the current site content (never overwrites)
npm run admin:create   # create your admin login (asks for email + password)
```

### What `db:init` creates

| Collection | Holds | Indexes |
| --- | --- | --- |
| `projects` | Projects and their case studies | `slug` (unique), `status + order` |
| `profiles` | Name, contact details, resume (one document) | `key` (unique) |
| `admins` | Admin accounts (scrypt password hashes) | `email` (unique) |
| `sessions` | Signed-in admin sessions (hashed tokens) | `admin`, `expiresAt` (**TTL** — expired sessions are deleted automatically) |
| `loginattempts` | Failed sign-ins, for rate limiting | `key + createdAt`, `createdAt` (**TTL** 15 minutes) |
| `images.files`, `images.chunks` | Uploaded images (GridFS) | `filename + uploadDate`, `files_id + n` (unique) |

The app also creates any missing index on startup, so a forgotten `db:init`
does not break anything — running it simply makes the setup explicit.

### Seeding the starter content

`npm run db:seed` copies the built-in content from `src/data/projectsData.js`
and `src/data/profileData.js` (the three existing projects and the resume) into
the database, so the admin panel starts with what the site shows today.
Existing documents are never overwritten; `npm run db:seed:force` overwrites
the seeded projects and the profile.

### Creating the admin account

There is deliberately **no public sign-up page** — accounts can only be created
by someone with database access, from the command line:

```bash
npm run admin:create
```

It asks for an email, an optional display name and a password (typed twice;
hidden while typing). Then sign in at **`/admin`** — locally
<http://localhost:5173/admin>.

- **Forgot the password?** `npm run admin:reset` sets a new one and signs out
  all of that admin's sessions.
- **Change the password** while signed in: *Admin → Account*.
- **Non-interactive shells** (CI, a hosting console): set `ADMIN_EMAIL` and
  `ADMIN_PASSWORD` as environment variables, run the script, then remove them.
  Prefer the interactive prompt on your own machine — inline variables can end
  up in your shell history.
- **More than one admin:** run `npm run admin:create` again with another email.

## 6. Deployment configuration

### Vercel (recommended — the repository is ready for it)

`vercel.json` routes `/api/*` to a single serverless function (`api/index.js`,
the same Express app used locally) and serves the built site for everything
else, with security headers.

1. Push the repository to GitHub and import it in Vercel. The framework preset
   (Vite), build command (`npm run build`) and output directory (`dist`) are
   picked up from `vercel.json`.
2. *Project → Settings → Environment Variables*:

   | Variable | Environment | Value |
   | --- | --- | --- |
   | `MONGODB_URI` | Production | Production connection string |
   | `MONGODB_URI` | Preview (optional) | A **separate** user/database for preview deployments |
   | `MONGODB_DB_NAME` | Production / Preview | e.g. `su_portfolio` / `su_portfolio_preview` (optional) |
   | `SESSION_TTL_HOURS` | All (optional) | e.g. `12` |

   Mark `MONGODB_URI` as **Sensitive**. Do not set `PORT` on Vercel.
3. In Atlas, allow Vercel to connect (*Network Access* → `0.0.0.0/0`, or install
   the **MongoDB Atlas integration** from the Vercel Marketplace, which
   configures access for you).
4. Deploy, then open `https://<your-domain>/api/health` and expect
   `"database": "connected"`.
5. **Initialize the production database from your computer** (Vercel has no
   shell): temporarily point `MONGODB_URI` in your local `.env` at the
   production database, then run `npm run db:init`, `npm run db:seed` and
   `npm run admin:create`. Switch `.env` back to your development database
   afterwards.
6. Sign in at `https://<your-domain>/admin`.

### Any Node.js host (Render, Railway, a VPS)

The production server (`server/index.js`) serves the built site and the API
from one process.

| Setting | Value |
| --- | --- |
| Build command | `npm ci && npm run build` |
| Start command | `npm start` |
| Node version | 20.19 or newer (22 LTS recommended) |
| Environment variables | `MONGODB_URI` (required), `MONGODB_DB_NAME`, `SESSION_TTL_HOURS`; the platform usually sets `PORT` |

Serve the site over **HTTPS** (all these platforms do it automatically) — the
admin session cookie is marked `Secure` whenever the request arrives over HTTPS.
For a fixed outgoing IP (VPS, some paid plans), add only that IP to Atlas
*Network Access*.

### Static-only hosts (GitHub Pages, plain Netlify)

These cannot run the API. The public site still works with the built-in
content, but the admin panel will not. Either use one of the options above, or
deploy the API on a Node host and proxy `/api/*` to it from the static host;
in that case set `ALLOWED_ORIGINS` on the API to the public site's origin.

## 7. Security guidelines

**Credentials**

- Keep `MONGODB_URI` only in `.env` (git-ignored) and in your host's
  environment settings. Never commit it, paste it into tickets or chats, or
  put it in a `VITE_*` variable.
- Use different database users for development and production, each limited
  to `readWrite` on its own database.
- Rotate the database password if it was ever exposed (*Atlas → Database
  Access → Edit → Edit Password*), then update it everywhere it is configured.
- Before pushing, check that no secret is tracked: `git status` should never
  list `.env`, and `git log --all -- .env` should print nothing. If a secret
  was ever committed, rotate it — removing it from history is not enough.

**Atlas network access**

- Serverless platforms such as Vercel do not have fixed outgoing IP addresses,
  so the usual setting is `0.0.0.0/0`. That is acceptable when the database
  user has a long random password, only `readWrite` on one database, and
  connections use TLS (always on with Atlas).
- Safer alternatives: the Vercel ↔ Atlas integration, a host with a static
  egress IP, or Atlas private networking on paid tiers.
- Remove IP entries you no longer use.

**What the application does**

- Admin accounts exist only via the CLI; there is no sign-up endpoint.
- Passwords are hashed with scrypt (memory-hard, per-user salt); sign-in takes
  the same time for unknown and known emails.
- Sign-in is rate limited in MongoDB (5 failures per email and 20 per IP
  address per 15 minutes), so the limit holds across serverless instances.
- Sessions use `HttpOnly`, `SameSite=Strict` cookies (`Secure` over HTTPS).
  They expire after `SESSION_TTL_HOURS` of inactivity and after 7 days at most,
  and changing the password signs out every other session.
- Every admin route requires a valid session with the admin role. Requests that
  change data must come from the site's own origin (CSRF protection).
- All input is validated on the server: unknown fields are dropped, lengths are
  limited, links and image URLs must be `http(s)` (no `javascript:` or `data:`),
  and query operators in user input are neutralized.
- Uploads must be real JPEG/PNG/WebP/GIF/AVIF files (checked by content, not
  by name), 4 MB at most. SVG is rejected.
- Responses carry security headers (Content-Security-Policy, X-Frame-Options,
  nosniff, Referrer-Policy); admin and auth responses are never cached.

**Backups**

The free Atlas tier has no automatic backups. Export the database regularly
(for example monthly) with the MongoDB Database Tools:

```bash
mongodump --uri="<your MONGODB_URI>" --db=su_portfolio --out=./backup-YYYY-MM-DD
```

Store backups outside the repository (they contain your content and image
files). Restore with `mongorestore`.

## 8. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `MONGODB_URI is not set` | No `.env`, or the variable is missing on the host | Create `.env` from `.env.example`; on Vercel add the variable and **redeploy**. |
| `Authentication failed` / `bad auth` | Wrong username/password, or unencoded special characters | Re-copy the string from Atlas, reset the user's password, URL-encode special characters. |
| `Timed out` / server selection timeout | Your IP (or Vercel) is not allowed in Atlas | *Network Access* → add your current IP (or `0.0.0.0/0` for serverless); wait a minute and retry. Corporate networks may block port 27017 — try another network. |
| `querySrv ENOTFOUND` / `ECONNREFUSED` with `mongodb+srv://` | DNS cannot resolve SRV records (some ISPs/routers) | Check the cluster host name; switch your DNS to 1.1.1.1 or 8.8.8.8; or use Atlas's standard (non-SRV) connection string. |
| `Connection refused` with `mongodb://127.0.0.1` | Local MongoDB isn't running | Start the MongoDB service or the Docker container. |
| `/api/health` says `not_configured` on Vercel | Variable added after the last deployment | Redeploy after adding environment variables. |
| Admin page: "can't reach the server" | API not running, or database down | Locally use `npm run dev` (not `npm run dev:client` alone); check `npm run db:check`. |
| "Incorrect email or password" for a new account | Created in another database (dev vs production) | Run `npm run db:check` with the same `.env` to see which database you are using; `npm run admin:reset` to set a new password. |
| "Too many sign-in attempts" | 5 failed attempts in 15 minutes | Wait 15 minutes, or `npm run admin:reset` from the command line. |
| Signed in, but saving says "Cross-site requests are not allowed" | The API is behind a proxy with a different host name | Set `ALLOWED_ORIGINS=https://<your-site-domain>` on the API. |
| Sign-in "works" but you are immediately signed out | Site served over plain HTTP behind an HTTPS proxy, or a misconfigured proxy | Serve over HTTPS; set `TRUST_PROXY` to the number of proxies. |
| Image upload fails: "Images must be 4 MB or smaller" | File is still too large after compression (e.g. a large GIF) | Export a smaller file or a WebP/PNG instead. |
| Atlas reports storage close to 512 MB | Many large uploads on the free tier | Delete unused projects/images (unused uploads are cleaned automatically), or upgrade the cluster. |
| Edits take ~30 seconds to appear on Vercel | CDN caching of public API responses | Expected. Use *Preview page* in the admin panel to see changes immediately. |
| Site shows the old/built-in content | API unreachable, so the site fell back to `src/data` | Check `/api/health`; the browser console (dev) logs `[content] API unavailable …`. |
